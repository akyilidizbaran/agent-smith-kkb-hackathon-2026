# Semantic Series Catalog Contract

`meta.series` is the **human-authored** half of the lakehouse's metadata. It is written only
from `catalog/series/*.yml`, which is reviewed and versioned in Git.

## Why it is separate from the operational metadata

| Table | Written by | Answers |
|---|---|---|
| `meta.artifact` | ingestion, automatically | which exact bytes arrived, when, from where |
| `meta.run` | ingestion, automatically | what a pipeline run did |
| `meta.dataset_version` | ingestion, automatically | which vintage is current |
| **`meta.series`** | **a human, via Git** | **what a series *means*** |

Operational metadata is a record of what happened and can always be regenerated by re-running
ingestion. Semantic metadata cannot: whether a number is a stock or a flow, whether it is in
milyon TL or percent, whether averaging it is meaningful — none of that is discoverable from
the bytes. It is a judgement backed by source evidence, so it belongs in review-able files
rather than in inference code.

Nothing infers a row into `meta.series`. A series appears there because someone read the
source documentation, wrote the entry, and it passed review.

## File format

```yaml
catalog_schema_version: "1.0"
source_id: evds

series:
  - series_id: evds:TP.KTF12
    native_code: TP.KTF12
    dataset_id: evds_housing_interest
    name_tr: Konut Kredisi Faiz Oranı (Akım, %)
    description: >-
      Serbest metin. Türkçe. Serinin ne ölçtüğünü ve tuzaklarını anlatır.
    aliases: [konut kredisi faizi, ev kredisi faizi, mortgage faizi]
    tags: [faiz, konut, kredi]
    frequency: weekly
    week_anchor: friday
    unit: pct
    measure_type: rate
    default_agg: avg
    semantic_confidence: verified
    semantic_source: source_service
    metadata_url: https://evds3.tcmb.gov.tr/igmevdsms-dis/serieList/type=json&code=TP.KTF12
    status: active
```

One file per `source_id`. The file's `source_id` is authoritative; a series whose namespace
disagrees with it is rejected.

## Fields

| Field | Required | Notes |
|---|---|---|
| `series_id` | yes | `<source_id>:<native key>`, validated by the shared identifier contract |
| `native_code` | yes | The source's own code, verbatim (`TP.KTF12`, `1534?Toplam`) |
| `dataset_id` | no | Links the series to the dataset a connector fetches. **If null, `status` must be `draft`** — enforced by the loader *and* a SQL CHECK |
| `name_tr` | yes | Turkish display name |
| `description` | **yes** | Turkish free text. This is how the agent layer recognizes a series, so it is required |
| `aliases` | no | What a user might actually say. Drives lexical search later |
| `tags` | no | Coarse grouping |
| `frequency` | yes | `daily, business_daily, weekly, biweekly, monthly, quarterly, semiannual, yearly` |
| `week_anchor` | weekly only | `monday`…`sunday`. **Required for weekly, forbidden otherwise** |
| `unit` | no (but see `verified`) | `pct`, `TRY_mn`, `index`, … `null` means "not established". An index series' unit is `index`; an unverified **base year** is a separate matter recorded in `description` |
| `measure_type` | yes | `stock, flow_periodic, flow_ytd, flow_cumulative, rate, ratio, index, count, unknown` |
| `default_agg` | no | `avg, sum, min, max, first, last` — EVDS's own vocabulary |
| `cumulative_reset` | `flow_ytd` only | `yearly`. **Required for `flow_ytd`, forbidden otherwise.** `since_inception` is absent by design — that case is `measure_type: flow_cumulative` |
| `semantic_confidence` | yes | `verified, derived, unknown` |
| `semantic_source` | yes | `manual, source_docs, source_service, profiler` |
| `metadata_url` | no | A **real** source URL. Never invent one |
| `status` | no | `active, deprecated, draft`. Defaults to `active` |

`first_obs` and `last_obs` exist as columns but **not** as catalog fields. They describe
observed coverage, are computed operationally, and the loader never writes or clears them.

## Confidence levels

| Level | Means |
|---|---|
| `verified` | Every semantic field, **including the unit**, is backed by evidence recorded in `docs/sources/` |
| `derived` | The classification follows from source-declared labels or flags, but something material is still unestablished |
| `unknown` | Not classified. No aggregation may be attached |

`verified` requires a non-null `unit`. A series whose unit is unestablished is at most
`derived` — the loader enforces this, because a "verified" series with no unit invites a
downstream layer to invent one.

## Validation rules

The loader rejects a catalog and writes nothing when any of these fail:

1. `catalog_schema_version` is not `1.0`
2. `source_id` is missing or not a valid slug
3. `series` is missing or empty
4. A `series_id` repeats — within a file **or** across files
5. `series_id` does not match the shared identifier contract
6. `series_id`'s namespace differs from the file's `source_id`
7. A required field is missing or blank (`series_id`, `native_code`, `name_tr`, `description`, `frequency`, `measure_type`, `semantic_confidence`, `semantic_source`)
8. A field is not in its vocabulary
9. An unsupported field name appears (a typo fails loudly rather than being dropped)
10. A weekly series has no `week_anchor`
11. A non-weekly series has a `week_anchor`
12. A `flow_ytd` series has no `cumulative_reset`, or declares `none`
13. A non-`flow_ytd` series has a `cumulative_reset`
14. `default_agg` is set while `semantic_confidence` or `measure_type` is `unknown`
15. `semantic_confidence: verified` with no `unit`
16. `aliases` or `tags` contain blanks or duplicates
17. `dataset_id` is null while `status` is not `draft`
18. The catalog directory does not exist, is not a directory, or contains no `.yml` files

**All files are validated before anything is written**, so a bad file cannot leave a partially
applied catalog. The write itself runs in one transaction and rolls back on failure.

### A missing catalog is an error, not an empty catalog

`load_catalog_files()` raises `CatalogError` when the directory is absent or holds no `.yml`
files. Returning an empty list there would let a wrong path or a deployment shipped without
`catalog/` start the lakehouse with **no semantics at all**, and every downstream layer would
read `meta.series` as legitimately empty. Turning the catalog off is spelled
`bootstrap_database(..., catalog_root=None)`; anything else is a failure. The connection is
closed before the error propagates.

## Loading behaviour

`bootstrap_database()` loads the catalog after creating the schemas. It is idempotent:

- Each record carries `catalog_content_sha256`, a hash of its semantic payload.
- A row whose hash is unchanged is **skipped entirely**, so `updated_at` does not churn on
  every bootstrap.
- A changed record is updated and `updated_at` moves.
- A new record is inserted.
- **Rows the catalog does not define are never deleted.** The loader upserts what it owns and
  leaves everything else alone, so a row added by hand or by a future process survives.

`bootstrap_database(..., catalog_root=None)` bootstraps the schema only.

## Current contents

| `series_id` | `dataset_id` | measure | frequency | unit | confidence |
|---|---|---|---|---|---|
| `evds:TP.KTF12` | `evds_housing_interest` | `rate` | weekly / friday | `pct` | `verified` |
| `evds:TP.KFE.TR` | `evds_housing_price_index` | `index` | monthly | `index` | `derived` |
| `bddk_monthly:1534_Toplam` | `bddk_monthly_housing_loans` | `stock` | monthly | `TRY_mn` | `verified` |
| `bddk_weekly:5690_3` | `bddk_weekly_housing_loans` | `stock` | weekly / friday | `TRY_mn` | `verified` |

`evds:TP.KFE.TR` is `derived` not because its unit is unknown — an index's unit is `index` —
but because **the base year is not established anywhere in this repository.** Differently-based
index series must not be spliced, and the series must not drive a real-terms conversion, until
the base is verified against EVDS's own series metadata.

The two housing-loan stock series are deliberately kept apart by their aliases: the monthly one
answers "konut kredisi", the weekly one only answers phrasings containing "haftalık" or "BDDK".
`kullandırılan konut kredisi` was removed from the monthly aliases because it reads as a *flow*
and would misroute a question about the balance.

## Known limitation: reading `TIMESTAMPTZ`

`updated_at` is `TIMESTAMPTZ`, matching `meta.artifact`. DuckDB converts that type to Python
through `pytz`, which is **not** a dependency of this project, so
`SELECT updated_at FROM meta.series` raises from Python. Read it as a number instead:

```sql
SELECT series_id, epoch_ms(updated_at) FROM meta.series
```

This is **not** specific to the catalog — it applies to every existing `TIMESTAMPTZ` column in
`meta.*`, including `meta.artifact.fetched_at`. Adding `pytz` would change the shared
dependency contract, so it is left as a team decision rather than resolved here.

## Relationship to `LAKEHOUSE_BUILD_PLAN.md`

The agent layer's build plan proposed this table. Where its proposal and this implementation
differ, the reason is recorded here rather than left as a silent divergence.

**Adopted from the plan:** catalog-before-Silver ordering · YAML under `catalog/series/` loaded
at bootstrap · the `measure_type` vocabulary · `semantic_confidence` levels · `aliases` as the
field that decides series-selection accuracy · `description` required · the shared frequency
terms (`daily|weekly|monthly|quarterly|yearly`) · `manual|source_docs|profiler` for
`semantic_source`.

**Deliberate differences:**

| Plan | Here | Why |
|---|---|---|
| `unit VARCHAR NOT NULL` | nullable | Every catalogued series currently has one, but a series whose unit is genuinely unestablished should say so rather than have one invented. `semantic_confidence: verified` *requires* a unit, so a unit-less series is visibly at most `derived`. |
| `dataset_id VARCHAR NOT NULL` | nullable, **only when `status = draft`** | A series can be catalogued before a connector exists. Forcing a value would mean inventing a `dataset_id` for something nothing fetches. The nullability is constrained rather than free: loader *and* SQL CHECK both reject a null `dataset_id` on an `active` series. |
| Add to `002_meta_tables.sql` | new `004_series_catalog.sql` | Reduces merge conflict with the parallel Silver work. `bootstrap_schema` globs `*.sql` in sorted order, so it is picked up with no code change. Numbered `004` because integration already carries `003_artifact_request_provenance.sql`. |
| `cumulative_reset: none|yearly|since_inception` | `none|yearly` | `since_inception` is already `measure_type: flow_cumulative`. Encoding it in two places lets the two disagree. |
| `semantic_source: manual|source_docs|profiler` | adds `source_service` | Metadata the source itself declares through an API (EVDS `serieList`) is stronger evidence than a human reading a document, and the distinction is worth keeping. |

**Not done in this round, by scope:** `is_subtotal` from BDDK's `bold` signal, `LakehouseClient`,
Silver/Gold, frequency conversion, cumulative decomposition.

## Adding a series

1. Confirm the code, frequency and semantics against `docs/sources/<source>.md` or a committed
   fixture. **Do not guess a series code.**
2. Add the entry to `catalog/series/<source_id>.yml`.
3. If a field cannot be evidenced, leave it null and set `semantic_confidence` accordingly
   rather than filling it in optimistically.
4. Run `make test`. The loader will reject the file if anything is inconsistent.
